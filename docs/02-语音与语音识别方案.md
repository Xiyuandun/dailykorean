# DailyKorean · 语音与语音识别方案

> 本文档详细说明韩语站的 **朗读（TTS）** 和 **语音识别（STT）** 实现，各通道优先级、降级逻辑与配置方法。
> 所有逻辑集中在 [js/speech.js](file:///workspace/dailykorean/js/speech.js) 的 `Speech` 对象。
> 最后更新：2026-09-13

---

## 一、朗读（TTS）总流程

入口统一走 `Speech.speak(text, rate)`（单句）和 `Speech.speakQueue(texts, rate)`（整段/队列）。真正的通道选择在 `_dispatchSpeak()` 里完成。

```
用户点"朗读" → speak() 或 speakQueue() → _dispatchSpeak(text, rate)
   │
   ├─ ① _staticAudioPath(text, rate)
   │     命中 data/audio.js 清单 → 直接播 audio/*.mp3（离线、零依赖、最稳）
   │
   ├─ ② useCloudTTS（需后端的 /tts，静态部署恒为 false）
   │
   ├─ ③ useGoogleTTS（Google 翻译韩语接口，前端直连、免费）
   │     800ms 未开始播放 → 判定被屏蔽 → 永久禁用本通道 → 走浏览器内置
   │
   ├─ ④ 安卓 Android
   │     ● 浏览器有韩语语音 → Web Speech 内置朗读
   │     ● 否则 → 有道 TTS（dictvoice，type=1）
   │
   ├─ ⑤ iOS / 桌面：浏览器有 speechSynthesis → Web Speech 内置（lang=ko-KR）
   │
   └─ ⑥ 无 speechSynthesis（如微信内嵌浏览器）→ 有道 TTS
```

**优先级速记：预生成 MP3 > Google 韩语 TTS > 浏览器内置韩语语音 > 有道 TTS。**

## 二、各 TTS 通道详解

### ① 预生成 MP3（最优先，最稳）
- 数据：`audio/*.mp3` + [data/audio.js](file:///workspace/dailykorean/data/audio.js)（`window.STATIC_AUDIO.normal`）。
- 查找：`_staticAudioPath()` 先把文本 `trim → toLowerCase → 连续空格压成单空格` 得到 key，再到清单里取文件名。
- **慢速**：若 `rate < 1` 且清单里有 `slow` 字段则用慢速音频（目前仅文章预生成了慢速）。
- ⚠️ 一旦改动韩语文本，key 的 sha1 会变，文件名变——必须用 `tools/gen_audio*.py` 重新生成对应 MP3，否则音频会失效。
- 生成方式见 [docs/04-数据生成与工具脚本.md](file:///workspace/dailykorean/docs/04-数据生成与工具脚本.md)。

### ② 云端 TTS（`/tts`，当前未启用）
- `useCloudTTS` 在**静态托管环境**（非 localhost/127.0.0.1/lhr.life/onrender.com）被置为 `false`，即 GitHub Pages 下永远关闭。
- `setVoice()` 里：静态环境保持 `useCloudTTS=false, useGoogleTTS=true`；有后端环境才重启用云端。
- POST 请求体：`{ text, voice, rate }` → 返回音频 blob → 用 objectURL 播放并缓存（`prefetch` 并发限 4）。
- 结论：**静态部署用不到，可忽略**。

### ③ Google 韩语 TTS（当前静态环境的默认自然语音）
- 接口：`https://translate.google.com/translate_tts?ie=UTF-8&q={text}&tl=ko&client=tw-ob`，直接返回 MP3。
- `tl='ko'` 固定韩语；`playbackRate` 调速；单次约 200 字符超长截断。
- **屏蔽检测**：设 800ms 定时器，若 `audio.play()` 后未进入播放即判定被屏蔽 → `doFallback()` 置 `useGoogleTTS=false`（本次会话不再试用）→ 回退浏览器内置语音。
- ⚠️ 中国大陆网络常屏蔽 translate.google.com，很多用户首次进入会走到回退。

### ④ 浏览器内置语音（Web Speech API）
- `speakFallback(text, rate)`，`u.lang='ko-KR'`，优先挑 `voices` 中 `lang` 以 `ko` 开头的语音，其次含 "Google" 的韩语语音。
- **iOS 关键坑**：`speechSynthesis.speak()` 必须在用户手势的**同步调用栈**内调用，不能包在 setTimeout/fetch/Promise 里，否则被静默拒绝。
- iOS 每次朗读后 `pause(); resume();` 重置引擎保证下一句出声；`speak()` 前对 iOS 也是先 cancel/pause/resume。
- 朗读 `.onerror` 时回退到有道 TTS。

### ⑤ 有道 TTS（垫底）
- 接口：`https://dict.youdao.com/dictvoice?audio={text}&type=1`（美式 `type=1`），中国大陆可用、无需 key。
- 单次 200 字符上限，超长需 `_splitText()` 分句（按 `.!?。！？` 切）。
- 可靠性差、易被限流挂起，仅在没有更优通道时使用。

### 停止朗读（重点）
`Speech.stop()` 会：
1. 清空队列 `_queue`；
2. 清队列卡死监视器 `_queueWatcher` 与 Google TTS 超时定时器 `_googleTtsTimer`、旧 `queuedTimers`；
3. `audio.pause(); audio.currentTime = 0;` 停所有 Audio 播放；
4. `synth.cancel()` 停 Web Speech。

> 切换 Tab（`app.js switchTab`）和页面隐藏/离开都会调 `stop()`，避免后台继续出声。

## 三、队列朗读（整段）与卡死保护
- `speakQueue(texts, rate)`：先 `stop()`，逐句 `{text, rate}` 进 `_queue`，然后 `_advanceQueue()` 逐句 `_dispatchSpeak`。
- 每句结束（audio `ended` 或 speech `onend`）自动推下一句。
- **卡死监视 `_armQueueWatcher`**：估算该句时长 `max(1800, text.length/12+2.5)s`，超时没动静就强制 `pause/cancel` 并跳下一句——解决"某句挂起导致整段静默"。
- `click 商 stab`：有道长句自动分句后，剩余入队首续播。

## 四、语音识别（STT）总流程

```
startRecognition(lang)
   │
   ├─ 方案A：云端识别（阿里云 DashScope） → 需配置 window.DAILY_CFG.sttUrl
   │     └─ 采集16kHz PCM → POST → 返回文本 text
   │
   └─ 方案B：纯前端（当前默认）
         ├─ iOS/iPad/桌面：浏览器 Web Speech API 优先（无需下载模型）
         ├─ 安卓(或浏览器无 Web Speech)：Vosk 离线识别
         │     ├─ vosk-browser.js 运行时按需加载(5.4MB)
         │     └─ 40MB 韩语模型分3片从 jsDelivr/CDN 下载后合并
         └─ 都不行 → 提示 unsupported
```

**当前状态：`sttUrl` 未配置 → 全程走方案B。安卓端识别依赖 Vosk 离线模型（40MB 下载较慢）或浏览器 Web Speech（国产机多被屏蔽），体验受限。** 若要改善安卓端识别，需接入云端（见第六节）。

### 方案A：云端识别（未启用）
- 启用条件：`window.DAILY_CFG.sttUrl` 配置为绝对地址，或相对 `/stt` 且当前页由本地/渲染平台提供。
- `_startCloudRecognition`：AudioContext + ScriptProcessor(4096) 采集，`_resamplePcm` 重采样到 **16kHz Int16 PCM**。
- `_finishCloudRecognition`：POST `{ audio: base64, sample_rate:16000, format:'pcm', model:'paraformer-realtime-v2' }`，返回 `data.text`。
- 失败自动回退到方案B。

### 方案B-1：浏览器 Web Speech（iOS/桌面优先）
- `_startWebSpeech(lang)`，`lang`=韩语 `ko-KR`。`continuous=true, interimResults=true`。
- `resultIndex` 取增量结果；final 进 `_recChunksText`，interim 存 `_recLastInterim` 兜底。
- 停止：`stopRecognition()` 调用 `_recSR.stop()` 等 `onend` 汇总；1.5s 超时兜底强制完成。
- 错误映射：`not-allowed/service-not-allowed→no-permission`、`network→network`、`no-speech→no-speech`、`audio-capture→audio-capture`。

### 方案B-2：Vosk 离线识别（安卓兜底）
- 三件套：`vosk-browser.js`（vendor 目录，按需动态注入加载）+ 40MB 韩语模型 + worker。
- 模型地址：`DAILY_CFG.renderModelUrl` 若配了则优先；否则取 `当前页绝对路径 + models/model.tar.gz`。
- `_modelChunks`：用 jsDelivr CDN 分 3 片（model.0/.1/.2）下载再合并（绕开 GitHub Pages 单文件下载超时 & 20MB 上限）。**注意 chunks 当前指到 `Xiyuandun/dailyenglish@main/models/` 仓库**——若韩语站模型未同步，需改成韩语站对应的 CDN 地址。
- `_preloadVoskModel`：在符合条件（静态环境、原函数 Android 或无 Web Speech、未启用云端）时，`init()` 后台自动预加载。
- `_waitVoskModel`：最大等 180s，经 `onStatus` 回调反馈进度（vosk-loading / vosk-ready / vosk-load-failed）。
- 关闭：`_stopVoskRecognition()` 停 recognizer/processor/source/stream/AudioContext，取 `_voskText`。

### 录音存档（MediaRecorder，与识别并行）
- 与识别**各自独立拿麦克风**，避免共享 stream 被 `SpeechRecognition.stop()` 关闭。
- 格式优先 `audio/webm;codecs=opus` → webm → mp4 → ogg/opus，每 100ms 输出。
- `stopRecording()` 返回 objectURL；`playRecording(url)` 用独立 `_recAudio` 回放。

## 五、语音选择（顶部下拉）
- `Speech.voiceOptions`：`sunhi`（女声·ko-KR-SunHiNeural）推荐、`injoon`（男声·ko-KR-InJoonNeural）。
- `setVoice()` 切换：清旧缓存、重置失败计数、按环境设 `useCloudTTS/useGoogleTTS`。
- 说明：韩语站的 voice 选择主要影响**预生成 MP3 与云端 TTS 的声线**；Google/内置/有道的 `tl`/`lang` 都固定韩语，不受其影响。

## 六、如何接入云端识别（阿里云 DashScope）

1. 部署一个后端函数（如阿里云函数计算），暴露 `POST /stt`，接口入参如 `_finishCloudRecognition` 所构造（见上），转发给 DashScope Paraformer-realtime-v2 返回 `{ text }`。
2. 在 `index.html` 的 `head` 里加：
   ```html
   <script>window.DAILY_CFG = { sttUrl: 'https://你的后端域名/stt' }</script>
   ```
   必须在 `data/audio.js` / `speech.js` 加载**之前**注入此全局变量。
3. 刷新页面后 `_useCloudSTT()` 返回 true，录音优先走云端；失败自动回退方案B。

> ⚠️ 若想让**安卓在 Android 上也能稳定识别**，这是推荐路线。当前未配置即绕行离线 Vosk / Web Speech，两者在安卓端体验都不佳。

## 七、常见语音问题排查速查
| 现象 | 原因 / 排查 |
|------|------------|
| 开始点朗读无声 | iOS 需真机用户手势触发；先走一次 click/touchend 解锁（无 Real）。或该网络屏蔽 Google TTS |
| Google TTS 被屏蔽后一直用难听的机器音 | 正常降级，或预生成 MP3 未覆盖该文本 |
| 安卓整段朗读卡住 | 有道 TTS 挂起；队列卡死监视会强制跳句，已内置缓解 |
| 安卓识别不出 / 下载慢 | 未接云端；Vosk 40MB 模型首次下载慢或 CDN 指向英文站仓库导致模型不对 |
| iOS 首句被吞 | 已在 init 里用非空极短串预热 speechSynthesis |
| 修改韩语文本后读音没变 | 文本≠音频 key；需重跑 gen_audio 生成新 MP3 |
