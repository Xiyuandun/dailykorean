## 一、部署：GitHub Pages（纯静态）

本站**无需后端**，所有逻辑跑在浏览器。只需把静态文件推到 GitHub 仓库，开 Pages 即可。

### 需要上传的内容
```
index.html
js/             # app/daycycle/speech/words/dialogue/reading/report/store + vendor/vosk-browser.js
data/days.js     # 30 天内容（大，必须传）
data/audio.js    # 预置音频清单
audio/*.mp3      # 千余个韩语朗读 MP3（大，必须传）
css/app.css
.nojekyll        # 让 Pages 不要按 Jekyll 处理
models/          # （可选）Vosk 离线模型，见 docs/02-第六节
```

### 不需要 / 不应上传（已在 .gitignore 忽略）
- 所有 `tools/*.py`、`tools/extra_scenes/*.json`（仅开发用）
- 后端脚本：`server.py`、`fc_deploy/`、`requirements.txt`、`render.yaml`、`vercel.json`、tunnel 脚本
- 日志、zip、临时文件

### 部署步骤
1. `git add` 上方静态文件（勿用 `git add -A`，避免误带上模型/后端脚本）。
2. `git commit` + `git push`。
3. 在 GitHub 仓库 Settings → Pages 打开分支部署（默认 `main` 根目录/或 `docs/`）。
4. 访问 `https://<用户名>.github.io/<仓库名>/` 验证。

## 二、改 JS 后必做：版本号 +1（重要！）

浏览器会缓存旧脚本。**每次改 `js/*.js`、`data/*.js` 后，必须把 [index.html](file:///workspace/dailykorean/index.html) 里对应 `<script src="...?v=N">` 的 `?v=` 数字 +1**，否则用户仍加载旧代码，问题"没修好"。

当前 index.html 引用的资源与版本号：
| 资源 | 当前 ?v= | 何时需要 +1 |
|------|---------|------------|
| js/store.js | 11 | 改存储/状态 |
| data/days.js | 5 | 重新生成 30 天内容 |
| data/audio.js | 2 | 重新生成音频清单 |
| js/daycycle.js | 2 | 改周期/天数逻辑 |
| js/speech.js | 26 | 改语音/识别 |
| js/words.js | 12 | 改单词模块 |
| js/dialogue.js | 17 | 改对话模块 |
| js/reading.js | 12 | 改阅读模块 |
| js/report.js | 10 | 改报告模块 |
| js/app.js | 12 | 改主控制器 |

> 页面 `meta` 已带 no-cache，但 `<script>` 版本号仍是强制刷新缓存的关键手段。

## 三、修改学习内容（30 天数据）

见 [docs/04-数据生成与工具脚本.md](file:///workspace/dailykorean/docs/04-数据生成与工具脚本.md)。核心原则：
1. **不要手改 `data/days.js`**——它是生成产物，大且结构冗余。
2. 改 `data/days_segments/*.json`（第 6~30 天）或工具内 PLAN（第 1~5 天）。
3. 重跑 `tools/gen_days_template.py` 生成 `days.js`。
4. 若改了韩语文本，重跑 `tools/gen_audio_fast.py` 重新生成对应 MP3 和 `audio.js`。
5. index.html 里 `days.js?v=` 和 `audio.js?v=` 各 +1。

## 四、历史常见问题与修复记录（Q&A 速查）

> 供未来对话定位"之前是怎么修的"。

### 4.1 英文站"停止朗读"无效，切换模块后仍继续（曾在英文站修过）
- **症状**：点停止按钮没反应；切 Tab 后上一模块的朗读还在响。
- **成因**：旧的停止逻辑用 `Audio.pause()` 和 `synth.cancel()`，但 Some 异步通道（Google 超时回调、speakQueue 的定时器）没被清，或 iOS 的 `resume()` 把已暂停的又拉活。
- **修法（要点）**：
  1. `stop()` 统一清空 `_queue`、清 Google 超时定时器与队列定时器、`pause()+currentTime=0`、`synth.cancel()`。
  2. iOS 场景避免 `resume()` 重读。
  3. 切 Tab（`app.js switchTab`）与 `beforeunload/pagehide/visibilitychange` 都在 `stop()`——确保任何切换/离开都断声。
- 韩语站此逻辑已在 [speech.js stop()](file:///workspace/dailykorean/js/speech.js#L920-L939) 与 [app.js](file:///workspace/dailykorean/js/app.js) 生效。

### 4.2 安卓手机语音识别不好用
- **根因**：未配置云端 STT（`window.DAILY_CFG.sttUrl` 为空），Android 端只能靠 Vosk 离线（下载 40MB 模型慢、CDN 预计指向英文站模型仓）或浏览器 Web Speech（国产机常被屏蔽）。→ 详见 [docs/02-第六节](file:///workspace/dailykorean/docs/02-语音与语音识别方案.md)。
- **建议**：欲改善安卓识别，接阿里云 DashScope 后端（FC 函数）。

### 4.3 韩语站 vs 英文站的差异
- 韩语站朗读首选**预生成 MP3**（最稳）+ Google 韩语 TTS；英文站类似但语音为英文女声。
- 韩语站**对话模块不采录音/不识别**，考核是"看中文默写韩语"（`dialogue.js`），与英文站"朗读评分"不同。
- 韩语站 voice 默认 `sunhi`/`injoon`（韩语），英文站默认 `jenny` 等。

## 五、遗留代码的英文站命名残留（维护要知晓）

韩语站是从英文站 fork 来的，部分文件里仍残留英文站命名，**不影响功能但记在心上，别困惑**：
- [store.js](file:///workspace/dailykorean/js/store.js)：`baseKey = 'dailyenglish_state_v1'`，故用户进度 key 实为 `dailyenglish_state_v1` / `dailyenglish_state_v1_<学习码>`，默认状态里 `voice: 'jenny'`（韩语站实际用的是 sunhi/injoon）。若想改成韩语专属 key/默认语音，需改这里并注意**会清空旧用户进度或与英文站数据冲突**。
- [speech.js](file:///workspace/dailykorean/js/speech.js) 与 [daycycle.js](file:///workspace/dailykorean/js/daycycle.js) 顶部注释仍写 "DailyEnglish"。
- 若同步改动，记得 `index.html` 里 `store.js?v=` +1。
